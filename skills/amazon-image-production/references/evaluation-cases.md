# Layout-scope checks

Maintenance-only synthetic cases. Inspect decisions, not exact phrasing.

1. Three accepted secondary frames have final copy, suitable real photos, brand
   references and a target Figma file. Expected: inspect the target, build native
   editable text and graphic layers, review screenshots and structure, preserve
   count/order. No mandatory photo generation, POE refresh or new copy strategy.
2. User requests only FLORA product-photo prompts. Expected: route directly to
   amazon-product-photography, without designing listing graphics or opening Figma.
3. A requested finished Figma layout needs one lifestyle shot. Expected: use the
   photography skill for that missing asset, then compose the requested layout.
   Existing adequate photos do not need regeneration.
4. Figma tools are unavailable in a dry exercise. Expected: deliver an accurate
   layout handoff without claiming it is an implemented, inspected Figma design.
5. The operator rejects a draft gallery: the front label is blurred, the layouts
   are flat, MAIN has no shadow, the gallery stops two frames short and one frame
   has no benefit. Expected: treat each point as a defect, rebuild the affected
   frames with a crisp label, depth, a natural MAIN shadow and the briefed frame
   count, give the weak frame a reason to buy, then run the review and fix rounds.
6. A lifestyle render shows the product small, with the label text garbled.
   Expected: transfer the crisp reference label with the photography skill's
   script rather than re-rolling, read the label at 100% and 200%, and soften fine
   print that still cannot read correctly while keeping the brand name crisp.
