# Reference pack and prompt handoff

## Ask for the smallest useful pack

For a pilot, use a real product photo, the desired shot or intended use, and two
or three liked photography references when available. These counts are starting
points, not requirements. A Figma file, approved copy and POE data are not required.

For a full gallery, helpful assets include front and three-quarter product views,
the important functional detail, packaging, a transparent cutout if one exists,
and real usage photography. Request only the missing angle needed for the chosen
shot. High-resolution originals are more useful than compressed chat screenshots.

A good reference note says what to adopt: lighting, background, camera angle,
product scale, photographic texture or color. One disliked example with a specific
reason can resolve ambiguity. Prefer the client's accepted work when available.
Brand colors may inform the scene; fonts and graphic layouts are not photo inputs.

## Separate the evidence roles

| ID | Role | Authority |
| --- | --- | --- |
| P1 | Product front | Identity, label, color, quantity; never style replacement |
| P2 | Product detail or second angle | Actual operation/geometry visible in this view |
| S1 | Style reference | Lighting, palette or material treatment only |
| C1 | Composition reference or sketch | Placement, view and empty space only |
| B1 | Brand color or packaging artwork | Exact supplied asset or specification |
| M1 | Selected master result | Continuity after product-fidelity review |

Select only references relevant to the shot. Resolve contradictory directions
explicitly: e.g. use C1's layout with S1's softer light, preserve P1's packaging.
Never call a moodboard product evidence. Do not use a contact sheet as a substitute
for individual uploads if the provider accepts separate references better.

## Per-image production packet

- Photo ID and intended use or shot objective.
- Asset operation and selected provider/model; mark unverified model settings.
- Ordered references with real file/asset IDs and roles. An unattached filename
  inside a prompt is not an uploaded reference.
- Exact prompt; optional targeted-edit prompt and mask when supported.
- Required aspect ratio, useful output resolution, placement/empty-space guidance.
- Acceptance check that is specific to the shot; candidate or final status.

## Synthetic prompt example

Assume the supplied inputs actually show one amber 75 ml spray bottle with a cream
label (P1), a warm bedroom lighting reference (S1), and a product-right layout (C1).
This demonstrates prompt structure, not a promise of product consistency.

> Create one square photographic scene for a pillow-spray listing. Image 1 defines
> the exact product: preserve its amber bottle shape, cream label, printed text,
> cap and proportions. Image 2 guides only the soft warm evening light and muted
> linen colors. Image 3 guides only composition. Show the bottle standing upright
> on a bedside table in the right half, with believable contact shadow. A softly
> focused unoccupied bed sits behind it. Keep the upper-left area quiet and low
> contrast for a headline added later. Show one bottle. Keep existing packaging
> print, but add no headline, badge or other graphic text to the scene.

If an exact label or silhouette changes, use the real cutout over a compatible
background or correct only the affected region with a supported edit operation.
Do not repair factual errors by hiding them in a small preview.

Reserved text space is a compositional requirement only. Typography and graphic
layout happen downstream and are not part of this photo deliverable.

Example targeted edit: keep product, framing and table position; soften only the
background contrast behind the headline area. Verify that the product survived.
