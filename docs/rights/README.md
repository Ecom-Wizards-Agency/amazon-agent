# Capability and authority

Grimoire means scheduled and Slack runs of wizards-ai. Amazon Agent means attended chat sessions. Both use the delegated Seller Central login **Merlin by Ecom Wizards** in shared Chrome on port 9223. Port 9222 is the operator's own browser, selected explicitly. Rights differ by approval gate, not by account identity. Authentication availability never broadens action rights.

The versioned source is `docs/rights/capability-matrix.json`. The team vault holds per-account SPP grant evidence, not a second executor catalogue. An SPP grant exposes a capability; it does not authorize a run. A `_local` standing permission may only narrow a row. It cannot enable a disabled executor, bypass a gate, or silently change the approved browser route.

States describe authority as verified on the row's date. `allowed` still requires the stated scope; `approval-gated` requires its named approval; `forbidden` is unavailable to that actor; `consent-outdated` requires renewed consent; `undocumented` and `open` are unresolved evidence gaps. The canary row's expiry is a documentation review deadline, not a runtime control. This matrix does not change executor behavior.

To add a capability, add a unique account-neutral row, both actors' states and instructions, identity/port, SPP labels, dated evidence, and at least one documentation pointer. Add code/config gates where available; `doc_only` requires a specific justification. Empty gate lists are invalid. Tag every dispatcher or closed-catalogue action `executor`, including disabled catalogue entries. Optional `modes` selects Grimoire prompt context (`*` means every run); it never grants execution authority.

Run the renderer, rights tests and documentation lint after edits. The sibling wizards-ai tests compare executor rows against its live dispatch table, configuration and closed Merlin catalogue. Update documentation and gate evidence in the same change. Keep credentials, client names and Slack IDs out of this file.
